# 羽毛球技术体系与细分技术族谱（草案）

> 状态：设计评审稿，尚未进入代码。  
> 目标：把当前 57 个平铺节点，重构成「领域 → 技术族 → 可训练技术 / 细分技术」的可折叠体系，并保留已有进度。

## 1. 为什么要调整

当前 57 个节点混了三个层级：

- 技术族：吊球、杀球、搓球、挑球
- 综合技术：正手吊球、正手搓球、接杀挡网
- 细分技术：劈吊、滑板吊、重杀、点杀、收搓、展搓

把 `劈吊`、`滑板吊` 和 `正手吊球` 放在同一层，会让「下一拍练什么」变得不清楚：到底该先把吊球整体练稳，还是直接练滑板吊？

调整后的目标是：

1. 先看技术族，再看基础技术，最后展开细分技术。
2. 技术族只做归类和聚合，不单独评级；可训练技术 / 细分技术各自有 0–4 级。
3. 正反手、直线 / 斜线、主动 / 被动、单打 / 双打是**属性**，不是无限拆节点的理由。
4. 已有 `skillId` 尽量保留，已有等级和评估历史不丢。
5. 不把战术、比赛管理、体能硬塞进技术细分。

## 2. 三层模型

```text
领域 Domain
└─ 技术族 Family（归类、聚合进度，不做 0–4 评估）
   └─ 可训练技术 Technique（独立 0–4 级）
      ├─ base：基础 / 综合技术
      └─ specialized：细分技术
```

### 2.1 技术族

技术族是一个**分组**，例如「吊球族」「搓球族」「接杀族」。它显示聚合进度，但不单独评级。

一个技术族可以有：

- 一个或多个 base 节点
- 若干 specialized 节点
- 一个 composite 综合节点（用于暂时不适合拆分的复合技术）

### 2.2 可训练技术 / 细分技术

每个节点有独立的 0–4 级标准、训练记录和评估历史。

- `base`：该族的基础或综合能力，例如「正手吊球」「搓球（综合）」
- `specialized`：需要单独练的细分，例如「收吊」「滑板吊」「正手收搓」
- `composite`：暂时保留的复合技术，例如「反手网前球」；后续可以再拆

### 2.3 属性，而不是节点

以下默认作为标签 / 筛选条件，不拆成新节点：

| 属性 | 例子 | 说明 |
|---|---|---|
| 正反手 | 正手 / 反手 | 动作机制差异足够大时才拆节点（如收搓 / 展搓、正反手勾对角） |
| 线路 | 直线 / 斜线 / 中路 | 落点选择，不是独立技术 |
| 情境 | 主动 / 均势 / 被动 | 执行条件，不是独立技术 |
| 项目 | 单打 / 双打 | 场景标签 |
| 击球点 | 高点 / 低点 | 技术内标准的一部分，不单独造节点 |

> 这条规则很重要：否则「正手搓球直线」「反手搓球斜线高点」会无限膨胀。

## 3. 术语与来源策略

### 3.1 术语状态

每个新增技术建议带以下字段：

- `name`：主名称
- `aliases`：别名 / 圈内叫法
- `termStatus`：`common` / `coach` / `needs-review`
- `sourceNote`：只写「通用教学共识」「待确认」或用户提供，不冒充书名 / 教练原话
- `applicableSides`：适用正手 / 反手 / 两侧
- `lines`：适用线路
- `contexts`：主动 / 被动 / 防守等

### 3.2 来源边界

本草案的判断来自通用羽毛球教学知识，而不是某本特定教材或某位教练的完整课程体系。公开网络资料只用于校验术语是否存在，不作为权威出处。

- 不声称引用某本书的页码。
- 不声称复刻刘辉、李宇轩等教练的课程体系。
- 如果你指定某套课程 / 教材 / 教练术语表，可以新增 `systemSource` 字段，以那份体系为主。
- 术语有地域差异的，标成 `needs-review`，不直接写死。

### 3.3 首批待确认术语

- 收吊 / 慢吊：是否为同一技术，还是两种不同发力
- 拦截吊：具体击球点和动作定义在教练之间是否统一
- 软压：是否作为杀球族独立细分，还是归入吊球 / 过渡球
- 快吊 / 快杀：与点杀、劈杀的区别是否足够稳定
- 正手侧移 / 反手侧移：是否拆成节点，还是只作为两侧移动的执行面
- 正手被动步法 / 反手被动步法：是否属于步法族，还是被动救球的步法标签
- 双打进攻轮转 / 防守轮转：是否属于技术细分，还是战术层

## 7. 数据模型调整

### 7.1 新增字段

```ts
type SkillRole = 'base' | 'specialized' | 'composite';
type TermStatus = 'common' | 'coach' | 'needs-review';

interface SkillFamily {
  id: string;
  domainId: DomainId;
  name: string;
  description: string;
  order: number;
}

interface Skill {
  // 现有字段保留
  familyId: string;
  role: SkillRole;
  aliases?: string[];
  termStatus: TermStatus;
  sourceNote?: string;
  applicableSides?: ('forehand' | 'backhand' | 'both')[];
  lines?: ('straight' | 'cross' | 'middle')[];
  contexts?: ('active' | 'neutral' | 'passive' | 'defense')[];
  disciplines?: ('singles' | 'doubles')[];
}
```

### 7.2 迁移原则

- 现有 57 个 `skillId` 全部保留。
- `劈吊`、`滑板吊`、`重杀`、`点杀`、`正手抽球`、`反手抽球` 仅调整 `familyId` 和 `role`，不改 ID。
- 已有 `progress`、`assessments` 不变；等级不会因为重构丢失。
- 新增细分使用稳定 ID；建议命名：
  - `net-spin-fh-close`
  - `net-spin-fh-open`
  - `lift-fh-flick`
  - `drop-fh-hold`
  - `smash-cut`
- 内容版本从当前版本升级，导出包保留 `contentVersion`。
- 旧导出导入时，未知的新节点没有进度；旧节点进度正常保留。

### 7.3 界面

- **图谱默认**：领域视图显示技术族 + base 节点；specialized 默认折叠。
- **展开**：点击技术族或 `+N 细分` 展开细分节点；手机保持列表优先。
- **详情**：显示所属技术族、同族节点、细分节点、相关属性。
- **列表**：按技术族分组，base 直接展开，specialized 可折叠。
- **统计**：技术族显示聚合进度；可训练节点显示各自 0–4 等级。
- **评估**：只有可训练技术 / 细分技术可评估，技术族不可评估。

## 8. 待确认问题

1. 「综合节点 + 侧向细分」是否同时保留？例如「上网步法」和「正手上网 / 反手上网」是否重复。
2. 反手网前球是否拆成反手放网、反手推球、反手挑球，还是保留为一个 composite。
3. 正手侧移 / 反手侧移、正手被动步法 / 反手被动步法是否值得成为独立节点。
4. 双打轮转是否放技术层；如果放战术层，就不做 0–4 技术评估。
5. 收吊 / 快吊 / 拦截吊 / 软压这些教练常用术语，是否按你认可的体系保留。
6. 是否以某本教材或某位教练的课程目录作为 `systemSource` 基准；如果有，请提供目录或术语表。

## 9. 参考边界

本文件不声称复刻某本书或某位教练的原始分类。它是一份以通用中文羽毛球教学概念为基础的体系草案；`劈吊`、`滑板吊`、`重杀`、`点杀`、`收搓`、`展搓`、`弹挑`、`推挑` 等术语在中文教学语境中常见，但具体定义和叫法仍建议由你或你的教练确认。

确认这份族谱后，再进入代码：先加 `familyId` / `role` 和迁移测试，再做细分节点的详情、列表和图谱折叠。
